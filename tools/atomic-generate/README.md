# Atomic canonical generator wrapper

`dclutch-atomic-generate` protects an accepted generated file from producer,
shape, and validator failures. It captures producer stdout in a `mktemp` file
inside the destination directory, preserves producer stderr, and renames the
temporary file over the destination only after every gate succeeds. The final
rename therefore stays on one filesystem. Failure removes only the temporary
file and leaves an existing destination byte-for-byte unchanged.

At least one semantic-shape check is mandatory. `--expect-first-line` is an
exact string comparison; `--expect-pattern` is an extended regular expression
searched in the complete output. `--min-lines` defaults to one. An optional
validator receives the temporary path as its final argument and may either
check or normalize that file; all shape gates run again afterward.

For example, a canonical Lean-generated Rust file can be replaced safely with:

```sh
tools/atomic-generate/dclutch-atomic-generate \
  --output crates/example-codec/src/generated.rs \
  --min-lines 20 \
  --expect-first-line '// @generated by EmitExampleRust.lean' \
  --expect-pattern '^pub const EXAMPLE_BYTES: usize = ' \
  --validator rustfmt \
  --validator-arg --edition \
  --validator-arg 2024 \
  -- sh -c 'cd formal/dclutch-semantics && exec lake env lean --run EmitExampleRust.lean'
```

The wrapper does not decide whether a generator is semantically correct. The
caller must choose a release-specific header/pattern and any formatter, parser,
or freshness validator needed by that output. It does not stage or commit the
result.

Run the hostile shell regression suite with:

```sh
tools/atomic-generate/tests/test.sh
```
