# dClutch compiled Direct controller experiment

This program is the successor-shaped Direct execution controller. Its inline
route accepts two independently signed limit intents and matcher-selected fill
and price coordinates. Its registered route accepts a 32-byte residual-fill
request and reads both already authenticated 232-byte registration states; it
does not repeat maker signatures. Both routes validate the current Clock slot,
canonical Market/Realm/capability/fee authority, exact controller-owned PDAs,
maker/outcome Position PDAs, canonical claim state, and real SPL Token state.

The instruction contains no claim or custody plans. A 568-byte transition
program generated by Lean checks the authenticated frame and derives gross
quote, floor fee, and successor nonces in a fixed-memory, safe-Rust interpreter.
Only those derived values are encoded into child requests. Inline execution
uses the 72-byte claim plan; registered execution emits only the 16-byte
positive-fill request, and the claim owner independently executes the
Lean-owned 168-byte residual program for both sides. Both use the same 40-byte
custody plan. The controller PDA and either the buyer replay or registration
PDA authorize child calls. The custody child executes two transfers through
the official SPL Token program.

The real-SVM campaign checks these runtime properties for the pinned artifacts:

- a transaction caller cannot impersonate the controller PDA;
- valid signatures with a wrong replay bump refuse without mutation;
- a matcher price outside a signed limit refuses without mutation;
- tampering with a signed fee-rate byte fails native Ed25519 verification;
- an admitted fill updates replay, claims, and real token custody; and
- a frozen fee destination fails after the first Token CPI and restores the
  journal, both replay roots, both Positions, source, seller, and venue accounts
  byte-for-byte.

The registered campaign additionally checks a wrong registration coordinate,
two successive GTC residual fills, terminal closure, real SPL delegation by the
buyer registration PDA, and transaction-wide rollback after a late frozen-venue
failure. Measured registered fills consume 59,129--59,138 CU end to end; their
legacy transaction is 762 bytes and the all-address v0 form is 271 bytes. The
current verifier-clean artifacts are 113,128 bytes for the controller and
20,568 bytes for the dual-profile claim owner.

This remains an experiment, not a release. The Market execution profile is
controller-owned but does not yet have immutable release-artifact admission.
The controller codec has a Lean semantic owner, exact length theorems, and four
Lean-emitted vectors matched byte-for-byte by the shared safe Rust and frontend
TypeScript codecs. Refinement theorems for both parsers remain open. Realm
selection and release authorization are authenticated for the inline route.
The registered successor now has a Lean-owned 232-byte state ABI and 168-byte
residual program consumed by the safe Rust codec. Registered fill dispatch is
now physically complete. Account-creation funding plus register, cancel, and
expire dispatch remain successor gates.
