# Dragon's Clutch swarm roadmap

Status date: 2026-08-19
Purpose: post-compaction execution map for Codex, Claude/Luade, and supervised
subagents.  This is a priority and dependency document, not a capability or
release claim.

[`../CURRENT_TRUTH.md`](../CURRENT_TRUTH.md) remains the claim vocabulary and
accepted-evidence ledger.  [`V1_BACKLOG.md`](V1_BACKLOG.md) remains the detailed
historical queue.  This document says what to do next, which work can safely run
in parallel, and which attractive work must wait.

## 1. North star and hard boundary

The strongest coherent product is a collateral-generic, operatorless claim
protocol in which:

1. degree-zero categorical and native degree-one through degree-three smooth
   B-spline claims retain distinct, exact semantics;
2. public value enters only when an authenticated source and prepaid mandatory
   work make resolution reachable;
3. candidate admission, verification, selection, settlement, lapse, and refund
   are one bounded authority lifecycle;
4. every economic compartment and every rent-bearing account has a named
   terminal disposition or an explicit permanent/tombstone classification;
5. proof, finite checking, host execution, SBF execution, release identity, and
   deployment remain separately visible evidence planes; and
6. the static Glass explains those facts without acquiring wallet, RPC,
   signing, submission, or truth authority.

Local/offline only remains the controlling authority boundary.  No lane may
deploy, push, publish, contact regulators, use a public RPC, sign with real
keys or funds, or infer production readiness.

## 3. Dependency-ordered milestones

### R1 — Seal the current evidence checkpoint

This is the immediate critical path.  It is deliberately smaller than the
ultimate protocol.

Required work:

1. Resolve all legitimate manifest and lockfile drift required by committed
   runtime paths; remove or separately account for unrelated worktree changes.
2. Freeze runtime source.  Build the exact default ELF at least twice from
   fresh outputs and compare bytes.
3. Run final-LTO diagnostic/survivor and direct `r10` stack audits on those
   bytes.  A diagnostic in a reachable first-party symbol is a STOP, even when
   host tests pass.
4. Rerun the current default-bank source refusal, ResolutionWork bank matrix,
   Direct V2 measured STOP, native point/redemption routes, and required
   rollback cases against the frozen ELF.
5. Capture exact CU, account counts, rent, reward schedule, and all explicit
   admission `None`/STOP rows.  Never clamp an inadmissible route into a quote.
6. Rebuild a committed source archive on `persvati`; use `hbox` for the heavy
   SBF/release campaign.  Record host/toolchain/archive identities and keep GPU
   detection separate from GPU execution.
7. Run dependency/license/archive checks and emit one clean schema-v2 baseline
   manifest from the final commit.  Check the manifest again after its
   manifest-only commit.
8. Reconcile `CURRENT_TRUTH.md`, both handoffs, the backlog, implementation
   status documents, and Draft 10 engineering claims to exactly those bytes.

Exit criterion: one clean source commit, one content identity, one default ELF,
one evidence ledger, one independently reproduced portable subset, and no
contradictory current-status prose.

Do not hold R1 hostage to live Direct V3, a production provider, universal
terminal cleanup, FHE optimality, or a filing.  Those are named later releases.

### R2 — Admit one production source profile

The default value gate is now safe, but the default protocol remains inert.
This is the highest-value missing production prerequisite.

Required work:

1. Select one real V1 provider profile from primary official specifications.
2. Freeze exact program/deployment identity, account semantics, parser version,
   scale/orientation, finality, retention, bucket uniqueness, and availability
   assumptions.
3. Implement the default release registry entry and immediate live-account,
   clock/config, receiver-post or CPI authentication required by that provider.
4. Join absent-state SourceSpec/Feed/Archive construction to ResolutionWork on
   one clean default ELF.  Include substitution, stale deployment, wrong
   parser, reorg/finality, missing bucket, and provider-unavailable refusals.
5. Fund the complete source/archive/repair/resolution workload at market value
   admission.  Provider existence without prepaid work is not liveness.
6. Keep multi-page archives, repair generations, long maturity horizons,
   cleanup, release succession, and cross-Realm feed reuse refused until each
   has a separate bounded design and evidence campaign.

Exit criterion: a blank local bank can accept value only for the exact compiled
provider release, construct its canonical source state, and finish the staged
resolution path without injected Clutch accounts.

### R3 — Replace Direct V2 with staged Direct V3

This is the largest currently modeled-but-not-live protocol gap.

Required work:

1. Version and encode the modeled V3 accounts: Epoch, Candidate, Window,
   WorkBudget, Reservation, receipt/pot or their modeled replacements.
2. Preserve the exact DonationLedger split for payer principal, prior and later
   unsolicited donations, work reward, and neutral sink.  Never infer a refund
   owner from a signer after creation.
3. Implement the bounded lifecycle:

   ```text
   OPEN -> FROZEN/SUBMISSION -> VERIFYING -> SELECTED -> SETTLED
                                  \-> LAPSED       \-> LAPSED
   ```

4. Retain the full verifier.  Stage one retained candidate per transaction;
   do not replace verification with trust in caller score/digest fields.
5. Make noncompetitive full-top-three attempts deterministic no-state
   refusals.  Bound competitive identities to the frozen grid/tick set.
6. Implement empty, preselection, and postselection lapse; typed
   `ACTIVE -> ENTITLED -> CONSUMED/RELEASED` reservation effects; displaced
   candidate refunds; and a compact durable terminal receipt.
7. Close the remaining model/wire boundaries: pre-Freeze release,
   predictable-PDA prefund normalization, BatchPolicy/deployment identity,
   schedule and reward adequacy, legacy V2 cleanup, and hostile prestate.
8. Run one real-bank five-candidate replacement/tie/permutation campaign with
   late-failure byte-and-lamport rollback, exact rent/reward conservation,
   lapse paths, settle, replay, and current-ELF stack/CU evidence.

Exit criterion: candidate admission through settlement or lapse is one
constructible, permissionless, funded, bounded, replay-closed SBF lifecycle.

### R4 — Version the terminal lifecycle

This is not a cleanup utility.  It is an account/economic ABI migration.

Required work:

1. Give every new refundable account an exact persisted rent-principal owner,
   independent exact payer deposit, monotone donation ledger, neutral sink,
   generation identity, and separately prepaid keeper budget.
2. Classify every persistent object as exactly one of:
   `REFUNDABLE_TRANSIENT`, `PERMANENT_INFRA`, `PERMANENT_TOMBSTONE`,
   `EXTERNAL_OWNER_STATE`, or `UNCLASSIFIED_STOP`.
3. Close economic liabilities before rent: reservations, free/reserved cash,
   internal balances, external supply, fractional credits/carry, Hoard locked
   liability, and every surplus/forfeiture compartment.
4. Freeze the low-volume/failure payout rule.  Equal failure payout is not
   neutral.  Preserve observation and paid repair without using Hoard principal
   or confiscating abandoned claims.
5. Decide native fractional redemption: exact admitted lots or authenticated
   numerator-credit accounts with a funded terminal remainder disposition.
6. Add new outcome mints with authenticated `MintCloseAuthority`; legacy mints
   without it are permanent infrastructure and cannot be retroactively called
   fully closeable.
7. Close leaves in dependency order while retaining compact generation/
   consumed-ID tombstones needed for replay safety.
8. Add source/artifact reference ownership so archives cannot be deleted while
   unresolved/retryable markets depend on them.

Exit criterion: a hostile terminal walk covers donations, holder burns,
fractional fragments, all lapse phases, rent refunds, stale replay, and
deterministic recreation attempts, and ends in the exact declared account set.

Current model checkpoint: `6dbe618` is independently green only for an
internal-claim V2 research profile. It deliberately refuses external bearer
issuance and supplies no live ABI, CPI, authority, rent-funding, migration, or
fractional-credit result. Use it to falsify a runtime design, not as terminal
runtime evidence.

Failure-policy research checkpoint: `EvidenceOnlyRecoveryV1` rejects numeric
failure resolution unless authenticated evidence has already selected a unique
vector. It models finite SOL-prepaid repair, recoverable dormancy, lot-scaled
new-market bearer units, explicit credit STOPs, authoritative Token-2022 zero,
and burn-only whole-collateral disposition. It remains MODEL-ONLY and supplies
no source theorem, live ABI, Token-2022 encoding/migration, measured repair
route, or terminal CPI authority.

## 4. Parallel swarm map

### Luna-sized mechanical lanes

These are high-volume but low-authority tasks.  They should produce small,
exact-path commits or read-only reports.

- stale-pin, stale-status, forbidden-claim, and broken-link scans;
- exact account-size/rent tables derived from codecs;
- Cargo lock, license, source, and manifest inventory checks;
- hostile codec matrices for truncation, trailing bytes, padding, reserved
  bytes, duplicate IDs, and cross-reference cycles;
- fixture/corpus digest regeneration and byte-for-byte comparison;
- frontend accessibility/mechanical gates: reduced motion, forced colors,
  keyboard order, touch targets, print, overflow, and fail-closed rendering;
- command/evidence transcript normalization and missing-row rejection tests;
- test census, ignored/TODO inventory, stale historical ELF labels, and
  claimed-versus-invoked intent scans.

Luna lanes must not decide economics, authority, refund ownership, semantic
equivalence, or promotion.

### Terra-sized bounded engineering lanes

- production-provider spec/adapter audit against primary material;
- V3 codec and hostile-byte suite after the schema is frozen;
- individual V3 state-transition adapters with exact pre/post models;
- ProgramTest fixtures, rollback snapshots, rent conservation, and CU matrices;
- terminal lifecycle inventory and dependency-order close planning;
- fail-closed Glass data contracts and evidence rendering;
- release manifest generation, independent archive gates, and truth-doc
  reconciliation;
- Draft 10 claim-delta and provenance tables without filing activity.

Each Terra lane should own a non-overlapping path set and a promotion gate.

### Frontier lanes that need one strong semantic owner

- Direct V3 authority and staged selection as a whole;
- production source finality/uniqueness and parser authority;
- failure payout, abandoned claims, and terminal surplus disposition;
- Rust/account/SBF refinement theorem boundaries;
- confidential settlement leakage, recovery, and optimality proof design.

Do not split these into many agents making local choices.  Parallelize their
tests, audits, fixtures, and proofs only after one owner freezes the semantics.

## 7. Attractive distractions

Do not prioritize these ahead of the milestones above:

- additional market shapes before source, liveness, selection, and terminal
  authority close;
- making Direct V2 Select fit by weakening verification;
- generic multi-page/repair/source generality before one production profile;
- live LP/runtime liquidity before the modeled authority boundary is designed;
- another FHE backend or accelerator survey before the leakage/recovery plan;
- categorical lowering presented as smooth-product support;
- frontend network/wallet/submit affordances before a frozen release manifest;
- mainnet, customer onboarding, real money, public RPCs, or deployment;
- filing or regulator contact without the explicit governance gates above.

## 8. Handoff protocol for Claude/Luade

At the start of every swarm:

1. Read `AGENTS.md`, `CURRENT_TRUTH.md`, this roadmap, and the exact active
   goal.  Treat older status prose as historical until reconciled.
2. Record `git status`, HEAD, dirty-path ownership, and every active agent's
   exact paths before editing.
3. Assign one semantic owner per invariant.  Other agents may build hostile
   tests and independent audits, but may not invent competing semantics in
   shared files.
4. Require each lane to report: exact paths, commit, evidence plane, commands,
   test counts, artifact identity, negative boundaries, and remaining STOPs.
5. Prefer falsifying tests and rollback snapshots over prose confidence.
6. Never promote dirty-tree evidence, a historical ELF, a mock-feature ELF, a
   model, or a finite bridge into a stronger plane.
7. Freeze runtime before the final artifact campaign.  Land truth, handoff, and
   manifest changes only after the evidence they describe is committed.

The correct end state is not “all boxes green.”  It is a repository in which
every green box has reproducible evidence, every unclosed obligation fails
closed, and the next dependency is obvious.
