# ADR-0004: offline-first work and separate mainnet gate

Status: accepted

## Context

Source publication, technical correctness, public-network deployment, venue
operation, solicitation, affiliated trading, and revenue are different acts. The
current product/facility classification and operator perimeter are unresolved.

## Decision

Proceed with AGPL specifications, proof, simulation, synthetic fixtures, host
tests, local-validator work, reproducible builds, and an unsigned static client.
Block wallet access, signing, RPC writes, deployment, live markets, real funds,
solicitation, and regulator contact unless separately and currently authorized.
Keep Gate L0 visible and independent of all engineering milestones.

## Consequences

- The project can produce valuable public research even if deployment is never
  viable.
- No engineering checklist can silently grant external authority.
- Any later deployment requires exact legal, security, economic, release, and
  user-authorization closure for the named act.

## Evidence required

For offline work: reproducible local evidence and provenance. For any future
deployment: the closure specified in the regulatory packet, deployment boundary,
release manifest, and an explicit current authorization.
