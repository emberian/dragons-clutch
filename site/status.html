Current boundary

A real local lifecycle, not a release

The current bounded program can found and fund a market, split complete sets, place and cancel portfolio orders, freeze the canonical book, check a submitted candidate through a resumable relation, select the best valid candidate admitted by the deadline, entitle its witness, and settle exact receipts and pots. The accepted Cycle-G registry does not yet uphold that selection property: unverified claims can exclude or evict valid candidates, and a verified-only repair is currently unsealed. A local keeper and the Operator Bench can drive that path without a Dragon-operated network service.

None of that makes this a deployed protocol. There is no signed release manifest, production program identity, official frontend URL, production source identity, nonzero fee policy, or value-bearing market. Local validators and fixtures are local evidence.

Three different frontends

This microsite is a static explanation and makes no network request. Glass, under apps/static-client, is an offline inspector and unsigned intent-byte compiler with no RPC or wallet. Operator Bench, under apps/operator, renders a loopback daemon that holds ephemeral local test signers. None is yet a production transaction client.

Run the checks locally

From the repository root, serve this site:

python3 -m http.server 9129 --bind 127.0.0.1 --directory site

Check Glass without an npm install (Node and npm must already be installed):

cd apps/static-client
npm test

Check the Operator browser modules and their exact-integer/accessibility invariants (still source/mechanical, not visual QA):

cd apps/operator
npm test
npm run check

Drive the complete local trading example:

CARGO_NET_OFFLINE=true scripts/run_operator_trade.sh

The trading gate normally takes several minutes. It waits on the local validator’s real clock for a short freeze deadline and then the fixed 1,000-slot candidate window. The Epoch screen shows the current slot, target, reason, and remaining slots; after settlement the script requires every reported conservation identity to close. It exercises the HTTP/event and bank lifecycle; it does not load the browser modules or constitute visual QA. The loopback daemon requires an exact local Host, same-origin JSON, and a fresh process-local capability cookie for its mutation and event endpoints.

The next architectural work

  1. Finish and adversarially test verified-only candidate admission; split submission and verification deadlines in the successor window.
  2. Measure 416-slice entitlement and build authenticated location/adjacency indexes; a rank locator alone is only half the cost.
  3. Repair the ResolutionWork model/runtime reward mismatch before using its liveness projection.
  4. Optimize the streamed checkpoint and repeated FreezeEpoch walks without weakening hostile-byte refusals.
  5. Version capacity profiles instead of quietly treating 16 outcomes and 64 orders as the product.
  6. Separate Realm-selected collateral CPI from Token-2022 claim issuance so legacy collateral can be supported without a DREGG branch.
  7. Promote the payoff compiler into an untrusted, independently checkable market-creation path.
