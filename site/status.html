Current boundary

A real local lifecycle, not a release

The current bounded program can found and fund a market, split complete sets, place and cancel portfolio orders, freeze the canonical book, check a submitted candidate through a resumable relation, select the best valid candidate admitted by the deadline, entitle its witness, and settle exact receipts and pots. The accepted Cycle-G artifact does not yet uphold that selection property: unverified claims can exclude or evict valid candidates. The current unsealed source repairs it and passes the complete default and mock-source bank matrices. A local keeper and the Operator Bench can drive that path without a Dragon-operated network service.

None of that makes this a deployed protocol. There is no signed release manifest, production program identity, official frontend URL, production source identity, nonzero fee policy, or value-bearing market. Local validators and fixtures are local evidence.

Two operator surfaces

This microsite is a static explanation and makes no network request. Glass, under apps/static-client, consumes release-bound, chain-derived sessions and server-constructed unsigned transactions from operatord. Neither surface loads wallet material, signs, or submits a transaction.

Run the checks locally

From the repository root, serve this site:

python3 -m http.server 9129 --bind 127.0.0.1 --directory site

Check Glass without an npm install (Node and npm must already be installed):

cd apps/static-client
npm test

Run the local-real provider seam without devnet SOL or public RPC:

programs/clutch-sbf/svm-tests/run_svm_tests.sh \
  --non-production-real-pyth-lab \
  real_pyth_router_verifies_then_post_update_and_clutch_append_are_atomic

The captured deployed router persists a pinned, Verified locally signed synthetic proof. In a later transaction, the captured receiver writes a canonical price update immediately before Clutch appends it. Missing adjacency refuses with the archive unchanged; wrong Config or feed rolls back both the receiver-created update and archive. The Program/ProgramData bytes are captured deployment bytes; guardian and Config state is freshly initialized local fixture state. The one-record archive then seals and resolves payout cell 1 because the entire admitted conservative interval [99,980,929, 100,019,071] lies there. This is a real program/ABI/crypto seam in a local bank, not a current network price, redemption/multi-boundary campaign, or production source profile.

The next architectural work

  1. Separate candidate submission and verification deadlines, and replace ScoreV1 with a complete-set-invariant, Sybil-neutral objective.
  2. Define a production semantic source profile and exercise a network-signed upgraded 3-of-5 payload; the synthetic 13-of-19 signed-RPC local campaign is complete.
  3. Build strict product-driven capability profiles; the current audited loader rent is 14.49529272 SOL, and the measured micro-optimization wave still leaves a 645,876-byte gap to ten SOL.
  4. Add authenticated owner-reservation and epoch-child accounting before re-enabling Position or epoch-root deletion.
  5. Build authenticated location/adjacency indexes and measure the maximum-page portfolio settlement variants; a rank locator alone is only half the cost.
  6. Separate Realm-selected collateral CPI from Token-2022 claim issuance so legacy collateral can be supported without a DREGG branch.
  7. Promote the payoff compiler into an independently checkable market-creation path, then add named transferable shaped claims, liquidity/exit, and wallet UX.
